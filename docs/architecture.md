# القرارات الهندسية للنسخة الأولى

## حدود العمليات

- `src/main`: SQLite والملفات والنسخ الاحتياطي ونوافذ الطباعة وحوارات النظام.
- `src/preload`: قائمة محددة من العمليات باستخدام contextBridge؛ لا exposes عامة لـ IPC أو Node.
- `src/renderer`: React وواجهة عربية واتجاه RTL وخط محلي.
- `src/shared`: التحقق من المدخلات والعقود والحسابات ومكوّن المستند المستخدم في المعاينة وPDF.

تم تفعيل sandbox وcontextIsolation وتعطيل nodeIntegration، والتحقق من نافذة وإطار ومصدر طلب IPC. تمنع النوافذ التنقل وفتح روابط أو webviews، وترفض أذونات المتصفح. CSP في الإنتاج لا تسمح بالبرامج النصية المضمّنة؛ استثناء التطوير وحده مطلوب لـ React Refresh.

مرجع القرار: [Electron security](https://www.electronjs.org/docs/latest/tutorial/security).

## حساب المبالغ

المدخلات نصوص عشرية، وتحوّل إلى أعداد BigInt صحيحة بمقياس معلوم: منزلتان للأسعار والضريبة وثلاث للكمية. لا تستخدم عمليات ضرب عائمة للحساب المحاسبي. تُحسب قيمة البند وتقرّب نصف لأعلى إلى أصغر وحدة للعملة، ثم يخصم مبلغ الخصم وتطبق الضريبة على الصافي. المجاميع تجمع نتائج البنود المقربة.

تُرفض القيم السالبة والكميات الصفرية والخصم الأكبر من البند والضرائب فوق 100% والمجاميع غير الآمنة لعدد JavaScript الصحيح. جميع العملات الحالية لها منزلتان. `NULL` يختلف عن الصفر ويحدد ظهور أعمدة الطباعة الاختيارية.

## SQLite والترحيلات

نستخدم `node:sqlite` المدمج في runtime الحالي بدلاً من إضافة ملحق native يتطلب إعادة بناء ABI. Electron وNode مثبتان عبر الاعتماديات وملف lock، واختبارات Electron تتحقق من توافق SQLite الفعلي.

الترحيلات مرقمة داخل `src/main/database.ts`، ويسجل `PRAGMA user_version` نسخة المخطط. كل ترحيل ضمن معاملة؛ أي قاعدة أحدث من التطبيق تُرفض. لا نغيّر ترحيلاً منشوراً، بل نضيف ترحيلاً جديداً واختبارات ترقية له.

الحقول المستخدمة للفهرسة والحساب مخزنة في أعمدة، ومحتوى المستند الكامل محفوظ كـ JSON snapshot. هذا قرار للنسخة المحلية الأولى لتثبيت بيانات البنود والشركة والقالب مع المستند وتجنب تعقيد جداول لا تحتاج تقارير مفصلة الآن. يمكن تطبيع البنود بترحيل عند إضافة التحليلات أو القيود المحاسبية.

يعمل الترقيم والحفظ معاً في `BEGIN IMMEDIATE`، مع قيد تفرد للرقم. التحديث يتطلب revision مطابقاً، ونوع المستند لا يتغير بعد ترقيمه. الاعتماد يمنع تعديل المستند؛ يمكن إنشاء نسخة جديدة برقم جديد. تغيير الإعدادات لا يغير المستندات المعتمدة.

## النسخ الاحتياطي

`VACUUM INTO` ينشئ ملفاً متسقاً مستقلاً، بما يشمل الصور المضمّنة. النسخ التلقائية عند الإغلاق، واليدوية عبر حوار حفظ. لا تُستبدل نسخة موجودة بصمت، ولا تُحذف سوى النسخ التلقائية التي ينشئها التطبيق فوق حد الاحتفاظ. هذه نسخ محلية؛ يوصى بنسخة خارج الجهاز. اختبار الاستعادة الحالي يعيد فتح نسخة بقاعدة مستقلة، وواجهة الاستعادة ما زالت مطلوبة.

مرجع API: [Node SQLite](https://nodejs.org/api/sqlite.html).

## التصدير

React واحد ينتج محتوى المعاينة والطباعة، مع هروب النصوص افتراضياً. نافذة طباعة معزولة بلا preload تحمل HTML محلياً مؤقتاً، وتنتظر الصور قبل توليد PDF. يُحذف الملف المؤقت وتُغلق النافذة بعد العملية. تكرار رؤوس الجدول وتجنب انقسام صفوفه عبر CSS. PDF هو المرجع النهائي لترقيم الصفحات، ولا تدّعي المعاينة الممتدة تمثيل فواصل الصفحات.

## التحقق

- اختبارات وحدة للحسابات والتقريب والرفض وحدود الدقة والتواريخ.
- اختبارات SQLite للحفظ وإعادة الفتح والترقيم وrevision وتجميد النسخة والنسخ الاحتياطي والمخطط الأحدث.
- اختبارات Electron لإنشاء مستند وإعادة فتحه واعتماده، وعزل Node، وإعدادات الشركة والأنواع والقوالب والنسخ وتصدير PDF متعدد الصفحات.
- GitHub Actions على Windows: تنسيق واختبارات وبناء وتجربة Electron وتعبئة حزمة.

## قوائم العملاء والمنتجات — مخطط v2

الجداول `customers` و`products` تخزن سجلات مستقلة مع UUID وrevision. مفتاح مطابقة العميل اسمه بعد NFKC وتوحيد المسافات وحالة الأحرف؛ مفتاح المنتج يجمع الاسم والعملة. لا ندمج حروفاً عربية مختلفة مثل الهمزات أو التاء المربوطة. هذه هوية مبسطة لنسخة التطبيق الحالية؛ العملاء المختلفون ذوو الاسم نفسه يحتاجون أسماء مميزة.

حقول customerId وproductId اختيارية للتوافق مع المستندات القديمة. تحفظ نسخة الاسم والسعر والوصف داخل المستند دائماً، وتعديل القائمة أو أرشفة سجل لا يعيد كتابة المستندات. منتجات العملات المختلفة مستقلة، وعملة المنتج المحفوظ لا تُغيّر بل ينشأ سجل للعملة الجديدة. المستند المنسوخ يحتفظ بعملته وروابطه.

إضافة الأسماء الجديدة جزء من معاملة حفظ المستند نفسها، بعد التحقق من revision والقالب والنوع. تُحفظ المنتجات الجديدة فقط؛ لا تُحدّث أسعار المنتجات الموجودة تلقائياً ولا تُلغى أرشفتها. لا يُطبّق خصم الفاتورة على السعر الافتراضي للقائمة. عند فشل أي بند تتراجع معاملة المستند والقوائم والترقيم بالكامل.

قبل ترقية قاعدة موجودة من v1 ينفذ VACUUM INTO إلى نسخة مستقلة باسم tesir-before-v1-to-v2-UUID.db. الترحيل ينشئ القوائم ثم يقرأ المستندات من الأحدث إنشاءً لاستخراج السجلات؛ لا يعدل payload لأي مستند. نسخ ما قبل الترقية لا تدخل تدوير النسخ التلقائية السبعة. إعادة فتح قاعدة v2 لا تعيد الاستيراد، لذا تبقى تعديلات القوائم والأرشفة كما اختارها المستخدم.
